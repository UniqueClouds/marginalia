# AGENTS.md — Marginalia site repo

Instructions for any agent (or human) working on the **Marginalia** site at
<https://uniqueclouds.github.io/marginalia/> (repo: `UniqueClouds/marginalia`).
Keep this file in sync with how the site is actually built — if you change the
build flow, update this file in the same commit.

The repo is a **public, deliberately sparse mirror** of a private research
workspace. `.gitignore` is default-deny (`/*` + explicit `!` whitelist); only
curated paths are ever committed. Do not commit raw corpora, drafts, secrets, or
the workspace behind `marginalia/`.

## Layout — source vs. generated

**Source of truth (edit these):**
- `marginalia/NNN-slug/` — canonical entry dirs; each has `note.zh.md` +
  `note.en.md` (optional `artifact.{zh,en}.md`, `reports/`, `docs/`)
- `marginalia/006-podcast-guide/artifact.{zh,en}.md` — podcast guide source
- `mkdocs.yml` — site config
- `docs/about.md`, `docs/about.en.md` — about page (hand-edited; **not** regenerated)
- `docs/assets/extra.css` — site styles
- `scripts/build_site_pages.py` — the docs generator
- `.github/workflows/deploy.yml` — CI (runs `mkdocs build` only)

**Generated by the script — NEVER hand-edit; always regen:**
- `docs/index.md`, `docs/index.en.md`
- `docs/entries/NNN-slug.{zh,en}.md`
- `docs/entries/reports/*.md`, `docs/entries/docs/*.md` (copied from entry subdirs)
- `docs/podcast-guide/index.md`, `docs/podcast-guide/index.en.md`
- `docs/podcast-guide/data/*` (copied)

## The mandatory regen loop

CI only runs `mkdocs build` — it does **not** regenerate docs. Before any push:

```bash
python scripts/build_site_pages.py   # regenerate docs/ pages from marginalia/
mkdocs build                         # verify locally
```

If you touch `marginalia/*`, `scripts/build_site_pages.py`, or `mkdocs.yml`, run
the regen loop, **commit the regenerated `docs/` files in the same commit**, then
push. Pushing source without regenerated docs = site and source drift.

## Bilingual rule — every page has a toggle

Every content page has an EN sibling + a top-of-page `🌐 语言 / Language` toggle
linking to it. Sibling pairs:

| Chinese | English |
|---|---|
| `docs/index.md` | `docs/index.en.md` |
| `docs/about.md` | `docs/about.en.md` |
| `docs/podcast-guide/index.md` | `docs/podcast-guide/index.en.md` |
| `docs/entries/NNN-slug.zh.md` | `docs/entries/NNN-slug.en.md` |

Entry pages get their toggle injected by `build_entries()` (the `lang_zh` /
`lang_en` helpers). Home/about/podcast toggles are written into the source
files directly. When you add a new page: add its sibling + toggle in the same
commit, wire both into `mkdocs.yml` nav (🌐 English group mirrors the Chinese
nav).

## Icon rule — emoji, never shortcodes

Use Unicode emoji (`📖`, `🎧`, `🌐`, `🐙`). Do **not** use `:material-*:`
shortcodes — the build does not enable the shortcode extension and they render
as literal text on the page. (We hit exactly this: cards showed
`:material-book-open-outline:` instead of an icon.)

## Internal link rule — link the `.md` source

MkDocs 1.6 link validation only resolves `.md` source files. Use:

- `[about](about.md)`, `[home EN](index.en.md)`,
  `[entry 001](entries/001-code-taste-discord.zh.md)`

Do **not** use directory-style `about/`, `index.en/`, `entries/NNN-….zh/` —
it triggers `unrecognized relative link` warnings. mkdocs converts `.md` to the
final directory URL automatically.

## Anchor rule — explicit `{#id}` for TOC targets

When a heading is the target of an in-page TOC link, add an explicit anchor via
`attr_list`:

```md
### Section name {#sec-x}
```

Do **not** rely on auto-generated slugs — Chinese/emoji headings produce slugs
that don't match a hand-written TOC. (The podcast guide's `#sec-a`..`#sec-f`
were broken exactly this way; they only worked after explicit `{#sec-x}` anchors
were added to the six section headings.)

## nav + not_in_nav

- `mkdocs.yml` `nav:` lists every primary page, grouped: 🏠首页 / 📖项目说明 /
  🎧播客清单 / 📚条目 Entries / 🌐 English (the English group mirrors the
  Chinese nav with EN siblings).
- Entry companion docs (`entries/reports/*.md`, `entries/docs/*.md`) are deep-link
  targets inside entry bodies, **not** navigation pages. Declare them under
  `not_in_nav:` so mkdocs doesn't warn about them.

## Deploy

Push to `main` → `.github/workflows/deploy.yml` runs `mkdocs build` → uploads
`site/` → GitHub Pages at <https://uniqueclouds.github.io/marginalia/>.

Local preview: `mkdocs serve --dev-addr 127.0.0.1:8000` →
<http://127.0.0.1:8000/marginalia/> (note the `/marginalia/` subdir that comes
from `site_url`).

## License — three places in sync

Site content is **CC BY-NC 4.0**. Three places must always agree:
- `mkdocs.yml` `copyright:`
- `README.md` License section
- `README.zh-CN.md` 许可 section

If you change the license, update all three in the same commit.

## Build verification gate

After every regen, `mkdocs build` must be WARNING-free. The only acceptable
notice is the Material for MkDocs 2.0 framework-upgrade banner (unrelated to
this repo). If you see `unrecognized relative link`, `contains a link ... not
found`, or `missing anchor` — fix the **source** (see link/anchor rules
above), not the warning. Do not silence warnings by editing generated files.
